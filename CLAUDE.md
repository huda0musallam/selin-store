\# Selin Baby Store — Project Instructions



\## Project Overview

Selin is a frontend-only e-commerce store for baby and children's essentials.



The store includes baby clothing, newborn essentials, feeding products, bath and care products, sleep products, toys, and accessories.



The design reference is the baby e-commerce website image provided by the user.



\## Technology Stack

\- React

\- Vite

\- TypeScript

\- CSS

\- React Router when needed

\- Lucide React for icons when needed



Inspect the existing environment before choosing or installing dependencies.



\## Frontend-Only Rules

\- No backend.

\- No database.

\- No real authentication service.

\- No real payment gateway.

\- Use local mock product data.

\- Use localStorage for appropriate client-side persistence.

\- Checkout must be a frontend demonstration only.



\## Development Workflow

1\. Work in small, clearly defined stages.

2\. Start with Plan Mode and inspect before implementing.

3\. Explain the proposed changes before implementation.

4\. Implement only the currently approved stage.

5\. Test each stage before proceeding.

6\. Wait for the user's approval before starting the next major stage.

7\. Never build the entire store in one task.



\## Design Rules

Follow design.md for the visual identity, colors, typography, layout, and components.



The store should be elegant, warm, modern, clean, and child-friendly.



Prioritize product photography, clear navigation, responsive layouts, and usability.



\## Code Quality

\- Use TypeScript and avoid unnecessary any types.

\- Use reusable React components.

\- Use semantic HTML and accessible controls.

\- Keep data, components, pages, and styles organized.

\- Avoid duplicated code and unnecessary dependencies.

\- Preserve existing working code.

\- Do not claim tests passed unless they were actually run.



\## Safety

\- Never run destructive commands without explicit approval.

\- Do not overwrite unrelated files.

\- Do not commit or push without permission.

\- Ask before making major architectural decisions.



\## Communication

Explain each stage in simple language.



Before implementation, describe the plan and files affected.



After implementation, report changes, checks performed, and remaining issues.



\## Current Status

The project is in the planning stage.



Do not implement the storefront until the user approves the plan.
